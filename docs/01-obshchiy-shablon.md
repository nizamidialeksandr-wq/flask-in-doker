# Общая часть страниц: base.html

## Зачем

Сейчас шапка, меню и подвал скопированы в каждый файл в `templates`. Пять страниц — пять
копий одного и того же меню. Добавить пункт значит поправить пять файлов и ничего не забыть.

Jinja умеет иначе: один файл с каркасом, остальные страницы только дописывают своё.

## Как это устроено

`templates/base.html` — каркас. В нём вся общая часть и «дырки»:

```html
<title>{% block title %}Мой сайт{% endblock %}</title>
...
<div class="content">
    {% block content %}{% endblock %}
</div>
```

`templates/home.html` — страница. От неё остаётся только содержимое:

```html
{% extends "base.html" %}

{% block title %}Главная{% endblock %}

{% block content %}
    <p>1 парграф</p>
{% endblock %}
```

Правила:

- `{% extends %}` стоит самой первой строкой файла.
- Имена блоков придумываешь сам, главное чтобы совпадали в каркасе и на странице.
- Текст внутри блока в `base.html` — это значение по умолчанию. Страница может его перекрыть,
  а может и не перекрывать.
- Всё, что вне блоков, страница поменять не может. Поэтому шапка и подвал везде одинаковые.
- `app.py` не меняется: `render_template("home.html")` работает как раньше.

## Ссылки через url_for

В каркасе ссылки меню написаны так:

```html
<a href="{{ url_for('contact') }}">связь</a>
```

Внутри кавычек не адрес, а **имя функции** из `app.py`:

```python
@app.route("/contact")
def contact():        # ← это имя и стоит в url_for('contact')
    return render_template("contact.html")
```

Flask сам подставит путь. Поменяешь `@app.route("/contact")` на `/svyaz` — все ссылки
починятся сами. Если ошибиться в имени, Flask скажет прямо:
`BuildError: Could not build url for endpoint 'kontakt'. Did you mean 'contact' instead?`

## Активный пункт меню

Раньше класс `active` проставлялся руками в каждом файле. Теперь его считает шаблон:

```html
<a class="{% if request.path == url_for('about') %}active{% endif %}" href="{{ url_for('about') }}">о себе</a>
```

`request` в шаблоне доступен сам по себе, передавать его из функции не нужно.

## Что сделано в этой ветке

- Добавлен `templates/base.html` — каркас со всей общей частью.
- `templates/home.html` переведён на него как образец: было 50 строк, стало 9.
- Остальные страницы (`about`, `contact`, `facts`, `eat`) не тронуты — это домашка.

## Как проверить

```bash
docker compose up --build
```

Открыть все пять страниц. Переведённая главная должна выглядеть точно так же, как раньше,
а активный пункт меню — подсвечиваться на той странице, где ты находишься.

## Если что-то не так

- `TemplateNotFound: base.html` — файл лежит не в `templates`.
- Страница пустая — забыл обернуть содержимое в `{% block content %}...{% endblock %}`.
- Меню и шапка задвоились — в файле страницы остался свой `<html>`, `<head>` или `<body>`.
  При `extends` от страницы остаются только блоки, больше ничего.

## Include: для кусков поменьше

Если повторяется не каркас, а кусок внутри страницы (карточка, блок отзыва), для этого есть

```html
{% include "card.html" %}
```

Разница простая: `extends` — страница внутри общей рамки, `include` — вставка куска в страницу.

Документация: <https://flask.palletsprojects.com/en/stable/patterns/templateinheritance/>
